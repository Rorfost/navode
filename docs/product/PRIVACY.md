# Navode privacy policy

This is the source policy for the deployed `/privacy` page. Last updated September 20, 2026.

Navode stores the configuration and content a person creates: theme and motion preferences, search provider, aliases, quick links, projects, workspaces, scratchpad text, snippets, focus timer state, Today priorities, live-widget preferences, and a bounded recent-action list. Recent actions contain labels and timestamps, not search queries or snippet contents. V2 can additionally store non-secret integration connection metadata; short-lived GitHub repository status, Google Calendar daily context, and public Codeforces context; plus configured project-health URLs and their short-lived local results. It does not store provider credentials in Navode settings.

The extension uses Chrome local storage; the optional web companion uses browser local storage. The V3 sync phase of the `2.0.0` release optionally adds account-backed sync and cloud snapshots for configuration a person explicitly chooses to upload. The first-sync preview identifies aliases, preferences, quick links, projects, workspaces, snippets, Today items, and integration connection metadata before upload. Scratchpad and recent-action history remain local-only by default. Cloud rows are account-scoped; device labels and last-seen times are retained for device management. GitHub, Google Calendar, and Codeforces are contacted only after explicit connection; Calendar access is read-only, and Codeforces uses no API key. Project-health checks contact only the exact URL a person configures, directly from their browser, and may be unavailable when browser or provider policy blocks the request.

Navode does not place provider credentials in settings or sync documents. If a future supported provider needs a server-side long-lived refresh token, it is held only in the V3.6 credential service as AES-GCM ciphertext with owner and provider binding, and is never returned by a Navode API or recorded in logs. Current V2 provider flows do not migrate credentials to that service. Operational API logs contain only route, status, duration, request ID, and typed error or rate-limit signals; they exclude user content, addresses, tokens, cookies, URLs, and user agents. Production log-sink retention is capped at 30 days.

If optional cloud sync is deployed, Cloudflare Workers and Hyperdrive process API traffic and connect to the selected PostgreSQL provider. Navode will identify the actual production provider accounts and any monitoring vendor in its deployment record before enabling sync. Account deletion deletes account-owned sessions, devices, sync data, cloud backups, provider credential ciphertext, and security events from the database; it does not delete the person's browser-local settings. Cloud backups otherwise remain until account deletion.

When a person intentionally invokes a command that opens an external destination, their browser navigates to that site. The selected site receives the data normally carried by that navigation, such as a search query sent to a supported search provider or a user-selected URL. Navode does not control those sites’ privacy practices.

People can export a local JSON backup, reset individual sections in Settings, or reset all Navode data. Removing extension data in Chrome also deletes the extension’s locally stored Navode data. For privacy questions and support, contact [support@rorfost.com](mailto:support@rorfost.com).
